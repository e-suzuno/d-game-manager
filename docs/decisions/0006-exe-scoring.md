# 0006 exe の選択を整数優先度からスコアリング方式へ再設計する

**決定日**: 2026-07-21（第6回レビューを受けて）

## 決定

exe の選択を**段階式スコアの降順で最上位1つを採用する方式**に変えた。

- 旧: 整数の優先度で分類し、同じ優先度なら辞書順で先頭を採る
- 新: 本命らしさスコア（フォルダ名と完全一致 > `Game.exe` > 双方向包含 > 一般名）＋ **helper-only 除外** ＋ **決定的タイブレーク**

あわせて **`crashreport` 系のハード除外を完全一致に限定**した。

## 背景

整数優先度では、同じ優先度の候補が複数あると本命が埋もれ、**アンインストーラや設定ツールが選ばれてしまう**ことがあった。また前方一致で `crashreport` を除外していたため、`CrashReportChronicle.exe` のような**正規のタイトルまで落として**しまっていた。

## 帰結

- 「フォルダ名と完全一致」を最上位（+100）に置いたことで、多くのケースが1段で決まる
- `setup` 等を含む名前の減点を **−10 と軽く**したのが要点。フォルダ名一致で打ち消せる程度にしてあるため、`SetupYourEscape.exe` のような helper 語を含む正規タイトルを落とさない
- **helper-only 除外**（`install.exe` / `config2.exe` / `SetupTool.exe` のように補助語だけで構成された名前）を分離したので、「実質候補が無いフォルダは非ゲーム」と判定できるようになった。再頒布物フォルダの偽検出が止まった
- タイブレークを **共通接頭辞長 → 名前の短さ → 辞書順** で完全に決定的にした。同じフォルダを2回スキャンして違う exe が選ばれると再現性が失われるため
- 判定の重み付けはヒューリスティックなので、**新しいエンジンや命名慣習が出たら調整が必要**になる。そのためスコアの根拠を `scan.go` のパッケージコメントに残している
