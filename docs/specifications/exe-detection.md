# exe の自動検出と制作ツールの推定

取り込み時に、フォルダから**ゲーム本体の `.exe` を1つ**選び、**制作ツールを推定**する。

`.exe` の自動検出はフォルダ取り込み時のスキャンでのみ行う（常時監視や再スキャンはしない）。

## 走査の範囲

- 選択したフォルダ自体がゲームフォルダなら**それを1件**として扱う。そうでなければ**直下のサブフォルダ**を走査する（複数ゲームが入った親フォルダをまとめて取り込めるようにするため）
- `.exe` の探索は**フォルダ直下のみ**。サブフォルダの exe は見ない
- サイズは配下すべてを再帰的に合計する
- タイトルは**フォルダ名**をそのまま使う（取り込み後にドロワーで変更できる）
- 登録済みのフォルダは候補から除外する

## exe 選択の3層

### 1. ハード除外

明らかにゲーム本体でないものを候補にしない。

- **前方一致で除外**: `unins*` / `UnityCrashHandler*` / `vcredist*` など
- **完全一致で除外**: `crashreport.exe` / `crashreporter.exe`

完全一致に限定しているのは、`CrashReportChronicle.exe` のような**正規のタイトルを誤って除外しない**ため。前方一致で切ると本体を落とす危険がある。

### 2. helper-only 除外と非ゲーム判定

「setup / config / install 語 ＋（空 | 数字 | tool などの補助接尾辞）」**だけ**で構成された名前は、補助ツールそのものと見なして候補から外す（`install.exe` / `config2.exe` / `installer.exe` / `SetupTool.exe`）。

`SetupYourEscape.exe` のように helper 語を**含むが正規のタイトル**であるものは候補に残す。

**実質的な候補が無くなったフォルダは「ゲームではない」と判定する。** 再頒布物のフォルダなどを偽検出しないため。

### 3. スコアリング

残った候補を「本命らしさ」のスコア降順で並べ、最上位の1つを採用する。

| 条件 | スコア |
|---|---|
| フォルダ名と完全一致 | +100 |
| `Game.exe` | +80 |
| フォルダ名との双方向包含（正規化名が3文字以上） | +50 |
| 一般名 | 0 |
| setup 等を名前に含む | −10 |

−10 は軽い減点にとどめる（フォルダ名一致で打ち消せる程度）。helper 語を含む正規タイトルを不当に落とさないため。

同点の場合は **共通接頭辞長 → 名前の短さ → 辞書順** の順で決める。**必ず決定的**にするのは、同じフォルダを2回スキャンしたときに違う exe が選ばれると再現性が失われるため。

### 名前の比較は正規化名で行う

記号・空白・括弧を除いた小文字を**正規化名**として比較する。これにより `SetupYourEscape_v1.0` / `(Steam)` / `[DL版]` / `v2_MyGame` のような接頭・接尾辞は無視される。

スコアリング方式へ再設計した経緯の詳細な設計記録は `internal/scan/scan.go` のパッケージコメントにある（コードの近くに置くのが適切な種類の記録なので docs には移していない）。

## 制作ツールの推定

フォルダ直下のファイル / ディレクトリ構成を根拠に判定する。**判別できなければ「未判別」**を入れる（[`tool-attribute.md`](tool-attribute.md)）。

判定の根拠となるファイル構成の一覧と評価順は [`import-flow.md`](../processes/import-flow.md) の「エンジン判別の根拠」を参照。

推定結果は **`games.tool` 属性として保存する。タグは作らない。**
