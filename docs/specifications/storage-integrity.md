# 保存先の整合性は検出して知らせるが自動削除はしない

ゲーム本体のフォルダや `.exe` は、アプリの外で削除・移動・リネームされる。ドライブが未接続になることもある。ライブラリの一覧が実体と矛盾したときに、それを**検出して利用者に知らせ、直す手段を提供する**。

## 4つの決めごと

### 1. `missing` は DB に永続化しない

実体があるかどうかは**実行時に `os.Stat` で確認する値**で、`games` に列を持たない（`store` から返る時点では常に空文字）。

OS 側の操作でいつでも変わる情報なので、列に持つと同期対象が二重になるだけで正確さは増さない。判定は `internal/health`、値の埋め込みは app 層（`CheckMissingGames`）が担う。

### 2. 一覧取得に存在確認を埋め込まない

未接続のネットワークドライブなどで `stat` が待たされると**初回描画がブロックされる**ため、`ListGames` には確認を含めない。

フロントは一覧を取得したあとに `CheckMissingGames` を非同期で呼び、**結果に含まれないゲームの `missing` は空に戻す**（実体が復帰したケースの反映を兼ねる）。

### 3. `stat` のエラーは種類を問わず「不在」として扱う

`ENOENT` だけを不在とすると、未接続ドライブや権限エラー — **どちらも結局ゲームを起動できない状態** — を「正常」と誤報告してしまう。エラーの種類で分岐せず、一律で不在とする。

### 4. 見つからない行を自動削除しない

外付けドライブの未接続やクラウド同期のオフロードでも、削除されたときと**まったく同じ結果**になる。誤判定で登録を消すと、ユーザーが積み上げたタグ・お気に入り・カバー・編集済みタイトルが失われる。

そのため**削除は必ずユーザーの明示操作に委ねる**（詳細ドロワーの削除、または「見つからない」ビューからの一括削除）。

## 保存先の再指定

`RelinkGame` でフォルダを選び直すと、保存先を貼り替えて `.exe` をスキャンで再検出し、サイズを再計算する。**タイトル・タグ・お気に入り・カバーは保たれる。**

- **選択したフォルダ自身の検出結果だけを採用する。** `scan.ScanFolder` は root がゲームフォルダでなければ直下のサブフォルダを返すため、親フォルダを誤って選んだときに黙って別フォルダへ貼り替えてしまうのを防ぐ
- **同じフォルダの選び直しも許可する。** 「exe だけリネームされた」ケースの復帰手段になる
- `folder_path` は UNIQUE なので、別のゲームが使っているフォルダを指定した場合は更新せずエラーになる

## 「見つからない」ビュー

実体が見つからないゲームが1件以上あるときだけ、サイドナビに「見つからない」ビューが現れる（**該当0件なら非表示**）。テーブル・ギャラリーではバッジ、詳細ドロワーでは警告バナーと再指定の導線を出す。

`missing` の種類は `folder`（フォルダ不在）と `exe`（実行ファイル不在）を区別する。

## 一括削除の失敗の扱い

「見つからない」ビューからの一括削除（`DeleteGames`）は**1件の失敗で中断しない**。成功した分は削除し、失敗した分を理由つきで返して利用者に見せる。
