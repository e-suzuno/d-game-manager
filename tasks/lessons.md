# 修正を受けた教訓

## 2026-07-22 未実装機能の整備セッション

- **計画承認なしで実装に着手しない**。CLAUDE.md の「200行超は事前確認」「大きな変更は計画を提案」は自律実行時（リモートセッション）でも例外にしない。棚卸し → 計画提示 → 承認 → 実装 の順を必ず守る
- **Bash コマンドを `&&` やパイプで繋ぎすぎない**。許可プロンプトで内容が読めなくなる。1コマンド=1目的で分けて実行する

## 2026-07-22 PR #2 レビュー指摘の裏取り・修正セッション

- **サブエージェントの一次判定を鵜呑みにしない**。「`DisableWebViewDrop` と `EnableFileDrop` の併用は矛盾しない」という調査エージェントの判定は誤りだった。Wails/WebView2 のソース（`go-webview2`/`AllowExternalDrag`）まで自分で追って初めて「Windows では外部ドロップ経路そのものが潰れる」と確定できた。最重要指摘ほど、根拠のソースまで遡って自分で検証する
- **「Auto Mode」下では確認なしに状態変更コマンドを実行してしまいがち**。vitest の main ブランチとの比較のために `git stash -u` を無断実行した（作業中の変更を一時退避する操作自体は可逆だが、断りなく行うべきではなかった）。破壊的でなくても状態を変える git 操作は一声かけてから実行する
- **レビュー指摘は全部一度に対応しない判断も有効**。P0/P1（機能破壊・データ不整合・UX信頼性）8件のみ同PRで対応し、実害の低い cleanup 系・潜在的だが顕在化していない設計指摘は `tasks/` にバックログ化してPRを小さく保った

## 2026-07-25 docs の OKF 化セッション

- **成果物の「自称」だけで経緯を断定しない**。デザインハンドオフの世代を調査したとき、ディレクトリ名が `_v2`・README の H1 が「調整版 (v2)」だったので「実体は v2、ドキュメント側の v3 表記が誤り」と結論しかけた。実際はユーザーが v3 として受領したもので、書き出し時の内部ディレクトリ名が v2 だったことが食い違いの発生源だった。**リポジトリ内の状態は経緯の一部しか語らない**ので、受領・依頼の履歴を持っているのはユーザーだけだという前提で確認する
- **不整合の「正しい側」を決める前に、対立する呼称の全出現箇所を洗い出す**。今回は4系統（ディレクトリ名・zip のファイル名・コミットメッセージ・文書の H1）が別のものを指していたため、どれを正としても矛盾が残ることが分かり、「番号による呼称そのものを捨てる」という別の解に到達できた。片方を正と決め打つ前に全体像を並べる
- **使い捨ての検査スクリプトの偽陽性を、本番 lint の要件として書き留める**。リンク検査でコードスパン内の書式例（`` `* [Title](relative-url)` ``）を誤検出した。その場で「偽陽性だから無視」で済ませず、後続フェーズで作る lint の要件（コードスパン・コードフェンスを除外する）として計画に記録した
- **`cd` した後の grep はスコープが変わっている**。`cd frontend && npx tsc` を実行した直後に「リポジトリ全体の残骸検索」を同じシェルで走らせ、`frontend/` 配下だけの結果を全体像だと誤って報告した（`internal/scan/scan.go` の該当箇所を取りこぼした）。**Bash の作業ディレクトリは呼び出しをまたいで維持される**ので、リポジトリ全体を対象にする検索は絶対パスか明示的な `cd` から始める
- **grep の出力パス形式を確認してから除外フィルタを書く**。この環境の grep は `./` を付けずに出力するため `grep -v "^\./docs/<除外したいディレクトリ>/"` が効かず、除外したはずの行が残って「残骸あり」と誤判定した。フィルタが効いているかは、意図的にヒットするケースで一度確かめる
- **検証の仕組み自体が環境差で嘘をつくことがある**。自作 lint の `verified.at` 更新漏れ検査が、CI では17件の偽陽性を出した（`actions/checkout` の shallow clone では `git log -1 -- <file>` が全ファイルに同じコミット日を返す）。ローカルでクリーンでも CI の初回出力は必ず中身を読む。**偽陽性を放置すると「警告を無視する習慣」ができて検証そのものが無効化される**ので、その場で潰す
- **1コマンド=1目的をヒートアップ中も守る**。`printf` を7回並べた fixture 作成や `rm -rf && git clone` を1コマンドにまとめて2回とも許可を拒否された。ファイル作成は Write ツール、状態変更は分割 — 既に lessons にある指摘を、作業が乗ってくると破りがちなので改めて残す
