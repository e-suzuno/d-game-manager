# tasks フォルダ

docs に載せるほどでない、作業単位の細かいメモを管理する場所。

## 何をどこで追跡するか

| 対象 | 置き場所 |
|---|---|
| 未着手・対応中の課題（バグ・改善・実機確認） | **GitHub Issue**（＝進捗の正） |
| セッション内の作業計画・チェックリスト | `tasks/` に作業トピックごとに1ファイル |
| 修正を受けた教訓（同じ失敗を繰り返さないための記録） | [`lessons.md`](lessons.md) |
| 確定した仕様・設計・決定 | `docs/`（正典。決定は `docs/decisions/`） |

`tasks/` は**作業中の状態**だけを持つ。残す価値のある結論は `docs/` へ、後日あらためて着手しうる課題は GitHub Issue へ移す。

## 運用ルール

- 作業トピックごとに 1 ファイル作成する（例: `ui-table.md`, `import-scan.md`）
- チェックボックス（`- [ ]`）で管理し、完了したら `- [x]` にする
- **トピックが完了したらファイルを削除する**。完了記録は git に残るので二重には持たない。未完の項目が残っている場合は、消す前に GitHub Issue  へ移す
- `lessons.md` は例外で、トピック単位ではなく継続的に追記する常設ファイル
